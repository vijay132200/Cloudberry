The patient portal and all dashboards must NOT behave like a static admin template with fake/generated metrics. The entire system should function dynamically using only actual database-driven patient activity and operational updates.

IMPORTANT:
All patient-facing metrics, charts, adherence scores, consistency tracking, trends, insights, and dashboard states must be calculated from real stored data inside the database and not hardcoded demo content except for explicitly marked demo credentials.

====================================================
REAL DATA LOGIC
====================================================

For every NEW patient signup (non-demo account):

INITIAL STATE:
- Daily check-ins = 0
- Weekly adherence = no data
- Weight trend = unavailable
- Behavioral consistency = unavailable
- Glucose trend = unavailable
- Insights = unavailable
- Coach review = not scheduled
- Messages = no messages yet
- Care team = not assigned yet

Dashboard should intelligently display:
- “No data recorded yet”
- “Complete your first check-in”
- “Awaiting care team assignment”
- “Review pending”
instead of showing fake placeholder analytics.

DO NOT preload fabricated metrics for real users.

====================================================
CHECK-IN LOGIC
====================================================

The daily check-in system must be fully database-driven.

Rules:
- If no check-in submitted today → dashboard shows “Check-in pending”
- Once completed → mark “Done for today”
- Weekly adherence must calculate dynamically based on completed check-ins
- Consistency score must calculate from actual logs
- Trends should gradually evolve over days/weeks of usage

Example:
If user completed 5 of 7 check-ins:
- adherence = 71%
- display only recorded days
- missing days = “No data”

Everything must evolve naturally over time using real patient activity.

====================================================
DASHBOARD DATA RULES
====================================================

ALL dashboard cards must pull real data from:
- daily check-ins
- uploaded glucose readings
- uploaded meals
- appointment records
- operations updates
- physician/dietician notes
- adherence history

DO NOT:
- use static JSON
- preload fake charts
- show generated trends before sufficient data exists

If insufficient data:
show intelligent empty states instead.

====================================================
OPERATIONS-DEPENDENT ACTIVATION LOGIC
====================================================

The patient dashboard must remain partially inactive until Operations/Admin configures the patient.

Before Operations assignment:
- No physician assigned
- No dietician assigned
- No caretaker assigned
- No meetings
- No care messages
- No clinical insights

Display:
- “Yet to be assigned”
- “No upcoming meetings”
- “No messages yet”
- “Care plan pending”

Only after Operations updates the patient profile and assigns care members should:
- meetings appear
- care messages appear
- intervention insights appear
- advanced dashboard analytics unlock
